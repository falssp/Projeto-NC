Taxonomia

Taxonomia

O que é
Sistema de nomenclatura padronizado de Campaign, Ad Group e Ad Name em todos os veículos digitais. Garante que qualquer pessoa entenda o que cada campanha representa.
Por que importa: Erros de taxonomia tiram dados do dashboard e do RROI. Janela de 30 dias para corrigir.
Estrutura — dois tipos obrigatórios
Campos Galileo Global
Padronizados pela UL Global. Separados por _. Não podem ser alterados sem autorização global.
Campos Freetext Brasil
Definidos localmente. Separados por |. Novos dropdowns alinham com UL Brasil antes de implementar.
Exemplo — Meta Campaign
cn010790-legacy-(hellmann's-world)_mayo_hellmann's_opauc_nocollab_awa_legacy|brdlft-y|promo|na
Ad Name
legacy-promo-4x5-meta-15s_vid_brand_nshop_15s_na_bsay_na_fed-stor-reel|brd|na|promo-15-SX00010803

IDs

IDs e relacionamento das linhas

Meta, TikTok e YouTube
1 linha = 1 ID único
Cada linha da RM tem um ID único que rastreia individualmente cada campanha / ad group / ad name.
Hierarquia de IDs
Campaign ID → Ad Group ID → Ad Name ID. O mesmo anúncio em campanhas ou Ad Groups diferentes recebe IDs vinculados ao seu Ad Group.
Pinterest, Twitter, DSP, Programático
1 ID único por Placement
A Flashtalking gera 1 ID único para cada Placement. Campaign e Ad Group IDs são do mesmo tipo sem hierarquia.
Atenção: a Stormx faz a mistura de informações de linhas diferentes ao gerar IDs, e isso pode causar erros de rastreamento. Sempre respeitar a hierarquia da RM.

Double Verify
Toda vez que for solicitada uma nova campanha para a criação do lado da Flashtalking, a agência precisa criar uma nova campanha na Double Verify. Sempre inserir o Campaign ID Flashtalking (campo Campaign ID no cabeçalho do ADP) e todos os publishers que vão veicular na campanha.

Flashtalking | Pontos importantes

Thread por campanha
Cada campanha deve ter uma thread do ADP e todas as solicitações para as campanhas devem ser realizadas nas respectivas threads para uma organização melhor e dessa forma é possível manter os históricos de solicitações.
Qual spec seguir
Quando a entrega do placement for por Tag, a criação das peças devem seguir as specs da Flashtalking. Quando for por Tracking, seguir as specs do Publisher. Em caso de dúvida, questionar o time de CS Flashtalking.
Social e veiculação
Para Social somente é aceito contadores. Nada deve ser veiculado sem a TAG ou CONTADOR da Flashtalking sem a autorização do cliente, uma vez que a Flashtalking tem de entregar os dados auditados para o cliente.
E-mail de contato
Sempre manter o e-mail unilever.as@adsmovil.com para todas as solicitações. Dessa forma toda a equipe do time de CS estará na cópia dos e-mails.

Validação de Dados

Validação de Dados | Diário, mensal e correções

Fluxo diário
Diariamente, o time de AdOps Stormx recebe alertas sobre novas taxonomias inseridas no banco de dados e sobre eventuais erros. Caso haja erro, o time reporta ao responsável no mesmo dia.
Fluxo mensal (RROI)
No final de cada mês, exportamos a base completa para validação. Os erros identificados seguem o mesmo fluxo de correção. É fundamental cumprir os prazos para garantir que os dados sejam contabilizados corretamente no dashboard e no RROI.
Correção DV360/YouTube IO
Insertion Order: Quando o IO tem mais de 120 caracteres e a plataforma não permite a substituição por limitação de caracteres, o ajuste é feito diretamente no banco de dados pela engenharia.

Ad Name: Os erros de Ad Name devem ser corrigidos tanto na plataforma quanto no banco de dados. O mídia informa ao time de BI sobre a taxonomia reduzida e envia a taxonomia correta.

Regras e Erros

Regras e Erros | Gerais

Taxonomia por plataforma
Proibido usar a taxonomia de uma plataforma em outra. Cada plataforma tem estrutura própria, e misturar compromete o banco.
Ad Name duplicado
Mesmo asset = Ad Name diferente por Ad Group. ID único; solicitar individualmente à Stormx.
Cópia de Ad Group/Ad Name
Nunca duplicar direto na plataforma, pois sufixos "cópia"/"copy" quebram a taxonomia. Sempre solicitar nova taxonomia à Stormx.
Caracteres especiais
Proibido: acentos, apóstrofo ('), travessão (—), underscore (_) e pipe (|). Usar apenas letras, números e hífen (-).
Taxonomia genérica
Exceção para quando o criativo ainda não chegou e a implementação será em feriado ou fora do horário comercial. Segue a estrutura correta com algumas informações genéricas. O time tem 24h para solicitar o ajuste com os dados corretos.

Regras e Erros

Regras e Erros | Por plataforma

TikTok Shop
Na plataforma do TikTok Shop só é permitido preencher o Campaign; não existe Ad Group nem Ad Name. A Stormx entrega 4 taxonomias na RM. Campaign, Ad Group e Ad Name vão na planilha de compra direta; o Campaign de TikTok Shop vai na plataforma.
Google PMax
Sem Ad Group: quebra extra de Format Type Local no Campaign (valor: "pmax"). Publisher = "google-pmax".
Google Search / Demand Gen
Search: Publisher = "google-search". Demand Gen: Publisher = "google-ads" (Google) ou "youtube" (YouTube).
Twitter Amplify
Campanhas Amplify não têm Ad Name. Publisher na RM = "Twitter-Amplify".
YouTube Masthead CPH
Masthead CPH: preencher Buying Type "cph".
Flashtalking via API
Ad Group + Ad Name unificados em Placement Name.
